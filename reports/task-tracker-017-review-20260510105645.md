## 指摘事項

- 指摘要約または「指摘なし」:
- 指摘なし。正常系を壊す問題は見当たらなかった。
- 確認した正常系: tracked detail panel の profile 表示は `TrackedSnapshot.ActiveProfileName` を基準に描画され、profile switch UI は frame 有無と独立して常時描画され、`Home.razor` の click handler から `TrackerProfileRequestService` と `TrackerCoordinator` を通じて control-only switch を発行した直後に `TrackedSnapshotStore.SwitchActiveProfile` で active profile 更新と frame clear が反映されるため、切替直後も UI が操作不能にならない。
- 関連根拠: `Tracker/Tracker.Server/Components/Vision/TrackerProfileControlViewState.cs:11`, `Tracker/Tracker.Server/Components/Pages/Home.razor:58`, `Tracker/Tracker.Server/Components/Pages/Home.razor:197`, `Tracker/Tracker.Server/Components/Vision/TrackedDetailsPanel.razor:35`, `Tracker/Tracker.Server/Tracking/TrackerProfileRequestService.cs:10`, `Tracker/Tracker.Server/Tracking/TrackerCoordinator.cs:64`, `Tracker/Tracker.Server/Tracking/TrackedSnapshotStore.cs:46`, `Tracker/Tracker.Tests/TrackerProfileRequestServiceTests.cs:19`, `Tracker/Tracker.Tests/TrackerCoordinatorTests.cs:144`

## リスク

- 未解決のリスクまたは後続対応:
- 非 blocking の保留事項として、`TrackedSnapshotStore` の初期 `activeProfileName` は `"default"` 固定で、起動時設定の `Tracker:ActiveProfileName` を初期反映する処理は見当たらなかった（`Tracker/Tracker.Server/Tracking/TrackedSnapshotStore.cs:10`, `Tracker/Tracker.Server/Program.cs:13`）。今回の `appsettings.json` では active profile も `"default"` なので正常系には影響しないが、将来 non-default profile を起動時 active にした場合は最初の frame 受信または profile switch 実行まで UI 表示がずれる余地がある。
- UI 連携は view-state / coordinator / service の単体テストで裏づけられている一方、`Home.razor` と `TrackedDetailsPanel.razor` のイベント配線を直接検証する component test は追加されていないため、将来の UI リファクタで退行が入る余地は残る。
