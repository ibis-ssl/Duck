## 指摘事項

- Blocking normal-path problems: no findings.
- ユーザー確認が必要な capability gap:
  - `TrackerPacketSnapshotRecord` は `PayloadBase64` を持つため raw tracker packet を後で復元できる設計・実装になっており、表示用 snapshot だけで終わる blocker は確認しなかった。一方、semantic summary は `Summary` の free-form string だけで、ball / robot count、team、robot id、代表位置、decode failure / skipped error などの構造化 field は `TRACKER-043` ではまだ固定されていない（`Tracker/Tracker.Server/Tracking/TrackerPacketSnapshotRecord.cs:15`、`Tracker/Tracker.Server/Tracking/TrackerPacketSnapshotRecord.cs:27`）。親が `TRACKER-043` 時点で構造化 semantic schema まで固定する期待なら追加作業が必要。既存 tracking どおり `TRACKER-044` で live sidecar 保存と source 集計を実装する前提なら、これは blocker ではなく `TRACKER-044` の契約強化点。
  - `tracker-server-cli-ui-detail-design.md` の後続タスク一覧は `TRACKER-043` が live sidecar 保存、`TRACKER-044` が replay / playback と書いているが、現 `tasks-status.md` は `TRACKER-043` を session folder / metadata / record / reader、`TRACKER-044` を live sidecar 保存としている（`Tracker/Tracker.Core/Design/tracker-server-cli-ui-detail-design.md:107`、`Tracker/Tracker.Core/Design/tracker-server-cli-ui-detail-design.md:108`、`Tracker/Tracker.Core/Design/tasks-status.md:35`、`Tracker/Tracker.Core/Design/tasks-status.md:36`）。今回のユーザー指示は live sidecar 実保存を `TRACKER-044` 範囲として許容しているため blocker にはしないが、親が design task numbering を同期するか判断する必要がある。
- Non-blocking concerns:
  - `TrackerCaptureOnSessionSnapshotContractTests` の sidecar record / reader 契約は reflection で public property と method の存在を確認する比重が高く、実 JSONL record を reader で round-trip して `ReceivedAt`、remote endpoint、source uuid/sourceName/role、tracked frame number/timestamp、`PayloadBase64` が保持されることまでは固定していない（`Tracker/Tracker.Tests/TrackerCaptureOnSessionSnapshotContractTests.cs:133`、`Tracker/Tracker.Tests/TrackerCaptureOnSessionSnapshotContractTests.cs:157`）。実装は `ReadRecords` で JSONL を deserialize するため現時点の正常系 blocker ではないが、`TRACKER-044` では writer と reader の実 round-trip、raw payload decode、semantic summary を契約テストにするべき。
  - metadata の `TrackerSnapshotLog.RecordCount` と `TrackerSnapshotSources` は常に `0` / `[]` として書かれる。これは `TRACKER-043` の「sidecar 未作成または record 0 件」表現としては整合しているが、`TRACKER-044` で sidecar writer が追記を始める際は metadata 更新または後処理 index の責務を明確にする必要がある（`Tracker/Tracker.Server/Vision/VisionPacketCaptureSession.cs:116`、`Tracker/Tracker.Server/Vision/VisionPacketCaptureSession.cs:122`）。
