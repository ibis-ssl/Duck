## 指摘事項

- blocking normal-path problems:
  1. tracking parameter の wiring 自体は広がりましたが、`TRACKER-013` の「外部設定から束縛される」という要件はまだ完了していません。設計では v1 の時点で「`appsettings` と設定束縛で全設定を外出しする」「既定値は埋め込み固定せず、すべて設定から注入する」と明記されています（`Tracker/Tracker.Core/Design/tracker-architecture-plan.md:495-507`）。一方で現状の `appsettings.json` では `Profiles.default.RobotTracker` / `BallTracker` / `KickDetector` が空オブジェクトのままで、今回 runtime 化した `ProcessNoise` / `MeasurementNoise` / `VisibilityHalfLifeSeconds` / `Gate` / `OutlierLimitMm` / `TrackLifetimeNs` / `KickSpeedThresholdMmPerS` / `ChipHeightThresholdMm` / `ContactMarginMm` の実値が設定ファイル側に一切現れていません（`Tracker/Tracker.Server/appsettings.json:19-35`）。その不足を埋めるため engine 側には依然として `DefaultVisibilityHalfLifeSeconds` / `DefaultBallProcessNoise` / kick/contact 既定値がハードコードされており（`Tracker/Tracker.Core/TrackerExecutionContracts.cs:21-22`, `Tracker/Tracker.Core/TrackerExecutionContracts.cs:1507-1544`, `Tracker/Tracker.Core/TrackerExecutionContracts.cs:1752-1777`）、`TrackerConfigurationBindingTests` も in-memory 設定では値を与えていますが、実際の shipped appsettings が同じ内容を持つことは確認していません（`Tracker/Tracker.Tests/TrackerConfigurationBindingTests.cs:88-126`）。この状態では「起動時設定が engine と publisher に反映される」以前に、起動時に参照される標準設定セット自体が外部設定へ完全に現れておらず、`TRACKER-013` の exit criteria（`Tracker/Tracker.Core/Design/tasks-status.md:33`）をまだ満たしません。
- user-confirmation-required gaps: なし。
- non-blocking held concerns:
  1. `TrackerConfigurationBindingTests` は新設パラメータの profile 値解決は確認していますが（`Tracker/Tracker.Tests/TrackerConfigurationBindingTests.cs:24-37`）、runtime override 優先順位を新設項目まで広げて検証しているわけではありません。resolver 実装は素直なので直ちに blocking ではありませんが、UI 側の一時上書き導入前に precedence 回帰を捕まえる小さな補強 test があると安全です。
- 指摘要約または「指摘なし」: blocking 1 件、held concern 1 件。engine/runtime wiring は概ね揃ったが、設定外出しの最後の一歩である `appsettings` 実体化が未完了。

## 結果

- 結果: `fail`。対象 60 テストは通過し、engine behavior の runtime wiring も広く追加されたが、tracking parameter の既定設定が `appsettings` に外出しされておらず、設計と task exit criteria が求める「外部設定から束縛される」状態にまだ達していないため、この task review は不合格。

## リスク

- 未解決のリスクまたは後続対応: `appsettings` に tracker parameter の既定値を明示し、コード内の埋め込み既定値との責務分担を設計どおりに整理したうえで再レビューが必要。可能なら新設 parameter の runtime override precedence を確認する config test も追加すると次段階で安全。
