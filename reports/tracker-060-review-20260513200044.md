## 結果

- 結果:
- `DiagnosticsPlaybackState.GetRealtimePlayIndex(...)` は timer 回数ではなく `currentWallClock - startWallClock` から `targetReceivedAt` を作り、`ReceivedAt <= targetReceivedAt` の latest index を二分探索で選んでいる。200Hz timeline / 1秒 wall-clock で index 200 へ進む regression test も追加されている。
- `Diagnostics.razor.cs` の Play loop は開始時の selected replay timeline tick `ReceivedAt` と wall-clock を保持し、各表示更新後に wall-clock から next index を再計算して `SelectTimelineByIndex` へ渡している。Play interval は約33.3ms固定で、timer tick 回数分だけ1つずつ進む実装にはなっていない。
- `Fast Forward` は `GetNextIndex` による1 tickずつの前進と、timestamp delta / speed multiplier / minimum interval による既存調査用挙動を維持している。
- `ShouldApplyTick(...)` は cancellation、mode、speed multiplier を引き続き確認しており、Stop / mode switch / speed switch の stale tick guard は維持されている。
- scrub / Field source / comparison は `SelectTimelineByIndex` -> `SelectReplayTimelineTick` -> `SyncComparisonState` / `ToReplayTimelineSelection` の既存経路を使い続けており、related tests でも saved alignment v2 / 任意 replay timeline tick 比較経路の regression は確認されなかった。
