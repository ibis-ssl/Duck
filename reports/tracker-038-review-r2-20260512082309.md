## 指摘事項

- [Medium] `Tracker.CaptureReplay` の settings 再生成で Kalman scale 系が失われる。`Tracker/Tracker.CaptureReplay/TrackerSettingsFactory.cs:23` は `CreateFromFile` の結果を常に `ApplyOverrides` に通すが、`ApplyOverrides` が作り直す `TrackerEngineSettings` では `KalmanInitialVelocityVariance`、`KalmanProcessNoiseScale`、`MeasurementNoiseVarianceScale` をコピーしていないため、`ResolvedTrackerOptions.EngineSettings` を含む capture metadata を読んでも scale が default に戻る。さらに profile/appsettings 形状の読み取りでも、`Tracker/Tracker.CaptureReplay/ReplaySettingsOptions.cs:76` の `TrackerEngineOptions` に Kalman scale property がなく、`Tracker/Tracker.CaptureReplay/TrackerSettingsFactory.cs:89` の `profileSettings` 生成でも scale を読んでいない。今回の r2 対応で engine 側は `Tracker/Tracker.Core/Engine/TrackerEngine/Settings.cs:174`、`Tracker/Tracker.Core/Engine/TrackerEngine/Settings.cs:185`、`Tracker/Tracker.Core/Engine/TrackerEngine/Settings.cs:195` により orientation filter へ既存 scale を反映できるようになったが、CaptureReplay replay 経路では metadata/profile の非既定 scale が落ちるため、初回 finding の「profile tuning scale 契約」は replay/調査ツール側でまだ解消されていない。

## 結果

- blocking finding 1 件。初回 finding は engine / server runtime 経路では概ね解消されているが、`Tracker.CaptureReplay` の settings / metadata replay 経路に Kalman scale の取りこぼしが残っている。
- `RobotTracker` への `OrientationMeasurementNoiseRad`、`OrientationProcessNoise`、`InitialAngularVelocityVariance`、`AngularVelocityLimitRadPerS` 追加、server profile / runtime override / clone / comparer / appsettings / README / binding tests への接続は確認した。
- engine 側の orientation measurement/process/initial angular velocity は、mm 用 covariance を流用せず、robot tracker parameter と既存 Kalman scale の既定値比を使う形になっている。
- focused test は 24 passed、full test は 153 passed を確認した。
- replay は `committedFrame=87` の Yellow 8 が `o=-1.571,w=0.239` で、evidence の記載と整合している。
- 実行形態は、依頼文の「nested Codex、codex exec、別 sub-agent 起動は禁止」に従い、別 agent は起動せず reviewer として repository を直接確認した。
