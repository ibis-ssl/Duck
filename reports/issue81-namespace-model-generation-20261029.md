# 課題81: 名前空間候補の構成を起動せず生成

対象はPR #84のI81-07Cで、起点は `963cfbee22943c3414feef197547c75645c532d9` である。DCPネットワーク合成の確認に使う実際の資源構成を生成し、通常構成の移行や実通信の成立とは区別する。

## 1. 目的

固定Aspire 13.5.4では、標準資源の名前空間引数と開始依存を表現できる。一方、DCPが既定の `Networks` と `RunArgs` をどう合成するかは、資源構成だけでは分からない。試験だけに別の構成を作らず、診断入口と試験が同じ生成処理を使う小単位を実装した。

## 2. 明示した診断入口

`Testing:NamespaceProbe:GenerateModel=true` を指定すると、所有元と依存側の標準 `ContainerResource` 各1件を生成し、JSONを標準出力へ返して終了する。`Build`、`Start`、`Run`へ進まず、DCP・コンテナ・HTTP待受を起動しない。未指定または明示的に無効では既存構成を保ち、不正な設定値や他の6つの明示設定との併用は拒否する。共通の所有排他ファイルを使う。

## 3. 生成する内容

固定`ASP.NET`イメージと `ImagePullPolicy.Never`、既存配布先の読み取り専用 `/app` 割当て、審判受信を無効にする引数を登録する。配布先が不足する場合は資源登録前に失敗し、作成・取得・代替起動を行わない。

所有元だけに127.0.0.1の動的`TCP`公開を登録し、依存側の公開先は0件にする。実行に属する物理名と実行・役割ラベル、依存側の `--network container:<owner>` と所有元への開始依存を同じ生成処理で構成する。JSONは実際の資源と注釈・引数から既知項目だけを取り出し、ホストの絶対保存先や環境設定・秘匿情報を出さない。

## 4. 検証

旧実装で併用と不正値が拒否されない失敗を保存した。続いて空文字・空白でも通常起動へ切り替わることを修正前の失敗として確認し、この新設定だけを厳密に検証するよう修正した。

最終の対象12件を含むAppHost全53件が成功し、両ビルドも復元処理なしで成功した。12件と53件は重なるため合計65件とはしない。最終3入力の指紋はビルド前後で一致し、終了値と出力指紋を保持する。先行10件・51件と、その時点の試験追記や実行記録は別に保存した。

新しい実入口の確認は終了値0で、実際に2資源のJSONを出力し、依存側の公開先は0件、ホスト絶対保存先は含まれなかった。共通排他の試験用保存先は解放・削除済みで、対象の試験・旧集約処理の残存はない。これは構成を生成する.NETプロセスの実行であり、DCPやコンテナは起動していない。

実生成物は `evidence/issue81-namespace-model-generation-20261029/model.json`、入力と出力の指紋は同保存先の `verification.json` に記録する。生ログは公開せず、実行値と最小証拠を保持する。



設計・進捗表の変更断片と本報告は、今回の4種の文書検査を各4入力で実行し、16件すべてに成功した。

## 5. 未確認と追跡の整理

生成物はDCPネットワーク設定の注入前であり、実際の合成、通信、再作成後の再結合を証明しない。通常・比較構成の6経路は置き換えていない。他のプログラム、固定イメージ、Docker設定は変更せず、追加の実機起動は行っていない。過去9841d996の受入を今回の実測へ移さない。

I81-08Aは既存の通常指摘解消と04ceの検証・CI記録へ追跡を合わせた。手動の完全ID・プロセスID・実行ファイルと対応する記号ファイル手順と後続受入を区別し、新しい自動接続機能や任意の固定デバッガー供給を追加必須にしない。I81-09の必要変更文書と全体独立最終確認も別に記録した。
