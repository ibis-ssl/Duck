# TRACKER-031 evidence

## タスク

- ID: TRACKER-031
- Title: camera 間の同一 robot ID 遠方 outlier で robot が瞬間移動する問題を修正する

## 原因

指定 diagnostics log の `2026-05-10 22:33:16.070 JST` は、ログ上では `2026-05-10T13:33:16.0703052+00:00` に対応する。

この frame の raw yellow robots には `Y1` が 2 件存在した。

- 誤 ID とみられる遠方観測: `Y1:x=-5275.8,y=-2255.7,o=3.242,c=1`
- 正常観測: `Y1:x=5161.2,y=-1997.1,o=2.891,c=1`

tracked output は `Y1:x=4321.6,y=-2019.5` になっていた。直前直後の tracked Y1 は以下の通り。

- `13:33:15.975`: `Y1:x=5160.5,y=-1999.5`
- `13:33:16.007`: `Y1:x=4864.7,y=-2006.6`
- `13:33:16.070`: `Y1:x=4321.6,y=-2019.5`
- `13:33:16.102`: `Y1:x=5160.4,y=-1998.8`

原因は camera-local robot state を `camera + team + robot id` で持つ一方、world merge は `team + robot id` で camera states を統合することにある。片方の camera が同一 ID の遠方誤検出を出すと、その camera-local track が fresh observation として reset され、別 camera の正常観測と同じ robot ID として merge されて中間点へ引っ張られていた。

## 変更

- 同一 frame の同じ `team + robot id` に複数 camera 観測がある場合、既存 camera-local track の予測位置に近い観測を anchor とする。
- anchor が存在する場合、anchor から movement gate より遠い別 camera 観測を far outlier として camera-local update から除外する。
- 単一観測しかない場合や、どの camera 観測も既存 track に近くない場合は従来どおり扱い、既存の outlier reset 契約を維持する。
- 回帰テスト `Update_DropsFarCameraRobotOutlierWhenAnotherCameraHasSameRobotNearTrack` を追加した。
