# TRACKER-038 evidence

## 対象

- diagnostics log: `Tracker/Tracker.Server/bin/Debug/net10.0/packet-captures/ssl-vision-packets-20260511T133110654Z-b94338b955704b8bb195e7d60bc7f68c.tracker-diagnostics.log`
- 指定箇所: `trackedFrame=3483`、`2026-05-11T13:31:13.5193696+00:00`
- 対象 robot: Yellow 8

## 原因切り分け

diagnostics log の raw detection では、`trackedFrame=3483` 付近の Yellow 8 は位置も向きもほぼ安定していた。

- raw Yellow 8 at `trackedFrame=3483`: `x=-3438.5,y=-4308.9,o=-1.569,c=1`
- tracked position at `trackedFrame=3483`: `x=-3439.2,y=-4310.4`

一方で同じ basename の `*.render-snapshots.jsonl.gz` には tracked orientation / angular velocity が記録されており、旧実装では raw orientation が `-1.56 rad` 付近で安定している間に、tracked Yellow 8 が次のように大きく回転していた。

- `trackedFrame=3483`: `orientationRad=-2.569751415339282`
- `trackedFrame=3483`: `angularVelocityRadPerS=-3.5952527898249076`

このため、原因は raw Vision 入力や camera 間 merge、表示処理ではなく、robot orientation filter の内部状態だった。既存実装は robot orientation axis に位置 mm 用の measurement variance / process noise / 初期速度分散を流用していたため、rad 単位の向き観測が十分に補正されず、過去の角速度が表示へ残り続けた。

## 修正

- robot orientation axis を位置 axis と分離し、rad 単位の measurement variance、process variance、初期角速度分散を使うようにした。
- orientation update に angular velocity clamp を追加し、静止 robot の小さな orientation jitter が大きな首振り角速度へ増幅されないようにした。
- `OrientationMeasurementNoiseRad`、`OrientationProcessNoise`、`InitialAngularVelocityVariance`、`AngularVelocityLimitRadPerS` を `RobotTracker` 設定へ外出しし、profile / runtime override / capture metadata replay から解決できるようにした。
- profile の `MeasurementNoiseVarianceScale`、`KalmanProcessNoiseScale`、`KalmanInitialVelocityVariance` は既定値比で orientation 用基準値へ反映し、mm 用 covariance を流用せずに既存 tuning 契約も維持した。
- `Tracker.CaptureReplay` の appsettings 形状と resolved metadata 形状の両方で、`KalmanInitialVelocityVariance`、`KalmanProcessNoiseScale`、`MeasurementNoiseVarianceScale` を落とさず復元するようにした。
- diagnostics log の `trackedRobotDetails` に `o=<orientation>,w=<angularVelocity>` を追加した。
- `Tracker.CaptureReplay` を汎用調査向けに改善した。
  - `--detail-filter frame==<n>` を追加した。
  - robot detail に `o` と `w` を出力した。
  - robot detail 表示を先頭 16 台まで広げ、ID 8 付近の確認で省略されにくくした。
  - CaptureReplay 内部型を `Tracker.CaptureReplay` namespace に閉じ、test project から参照しても既存の同名 test 型と衝突しないようにした。

```bash
  --settings Tracker/Tracker.Server/bin/Debug/net10.0/packet-captures/ssl-vision-packets-20260511T133110654Z-b94338b955704b8bb195e7d60bc7f68c.metadata.json \
  --detail-filter 'frame>=87' \
  --detail-filter 'frame<=87' \
  --max-details 1
```

結果抜粋:

```text
rawFrame=6965/6966 committedFrame=87
Y8:x=-3440.9,y=-4309.5,o=-1.571,w=0.239,vis=1.000
```

capture を先頭から replay するため committed frame number は元 diagnostics log の `trackedFrame=3483` とは一致しない。元 diagnostics log の該当時刻近傍は raw frame `6964/6965` であり、replay では raw frame `6965/6966` を含む `committedFrame=87` が対応する確認点になる。修正後は raw orientation `-1.56 rad` 付近に対して tracked orientation も `-1.571 rad`、angular velocity は `0.239 rad/s` に収まり、旧 snapshot の `-2.570 rad / -3.595 rad/s` の首振り状態は再現しない。
