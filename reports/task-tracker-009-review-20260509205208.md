## 指摘事項

- blocking normal-path problems:
  1. `[high]` `Tracker/Tracker.Core/TrackerExecutionContracts.cs:488-504` `MergedBallState.InternalTrackId` を `contributingStates.Min(state => state.LocalTrackId)` で毎 frame 再計算しているため、同じ物理 ball でも見えている camera の集合が変わるだけで track id が切り替わります。たとえば 2 camera で merge されていた ball が次 frame で片方の camera だけ可視になると、`PrimaryBallTrackId` と secondary sort tie-break が別 id へ飛び、後続 task の kick/contact metadata が ball identity を継続できません。
  2. `[medium]` `Tracker/Tracker.Core/TrackerExecutionContracts.cs:471-493` cluster 生成が stale/fresh を分ける前の `cameraBallTrackStates` 全体を使っているため、予測だけの stale track が 2 つの fresh ball を橋渡しして 1 cluster に潰せます。`freshStates` で重み付け対象を絞っても cluster 自体はもう壊れているので、multi-ball + 一時欠測の通常系で別 ball を誤統合します。
- user-confirmation-required gaps:
  1. `[medium]` `Tracker/Tracker.Core/TrackerExecutionContracts.cs:494-513`、`Tracker/Tracker.Core/Design/tasks-status.md:14`、`Tracker/Tracker.Core/Design/tracker-architecture-plan.md:753-760` task の exit criteria と設計は uncertainty-weighted merge を要求していますが、現実の実装は `Visibility/Confidence` をそのまま重みにした平均で、uncertainty state も保持していません。この task で完了扱いにするなら scope 追加が必要で、confidence-weighted でよいなら設計と tracking 文言の明示更新が必要です。

  - なし。
