## Existing configuration feasibility review
- Read --help from the unchanged Simulator and GC images using disposable --network none containers; neither image was pulled or modified.
- Simulator exposes --localhost, not a destination list. Pinned framework source has a single SSLVisionServer/RoboCupSSLServer and one m_server.send(data). SimulatorConfig.vision_port can replace its port, but cannot create a second simultaneous destination. Reference: https://github.com/ibis-ssl/framework/blob/a52b6bdecd97a277544dd6f275afbf4483781e12/src/simulator/simulator.cpp (handleDatagrams vision_port, SSLVisionServer, localhost option).
- GC v3.20.3 visionReceiver feeds each decoded packet into geometry/detection callbacks; no forwarding output is exposed. https://github.com/RoboCup-SSL/ssl-game-controller/blob/v3.20.3/internal/app/vision/visionReceiver.go
- GC go.mod fixes ssl-go-tools v1.11.0. Its MulticastServer resolves the configured address but binds net.IPv4zero at the configured port using SO_REUSEADDR/SO_REUSEPORT, then joins a group on selected interfaces. https://github.com/RoboCup-SSL/ssl-go-tools/blob/v1.11.0/pkg/sslnet/multicast_server.go
- Therefore changing GC group IP or skipping loopback is not a selective local-address bind: it still listens on wildcard10020. Excluding all interfaces or moving to a different port can prevent the collision, but does not deliver Vision to GC. Moving Simulator vision_port similarly does not fan out to two ports. These are not equivalent fixes and were not implemented.
- No supported existing setting was found that simultaneously delivers the same Vision stream to Windows RuntimeHost and GC in the tested host-network topology. This is a bounded conclusion from the pinned code, current image CLI, and the controlled experiment, not proof that every possible network architecture is impossible.
- Next decision: do not repeatedly toggle multicast/localhost or silently disable GC Vision. Either investigate an explicitly permitted network topology that genuinely preserves multicast across the boundary, or obtain approval for a design/constraint change enabling real fanout. Current single-destination implementation must not be merged as a full fix without that decision and all-consumer validation.
