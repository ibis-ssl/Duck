## Archive finalization gate

full-stack job は archive-finalization gate で失敗した。既存 cleanup は AppHost を停止して DCP container が消えた後に AutoRef の停止状態を調べていた。成果物には停止前の AutoRef inspect (`Running=true`)、空の `created-container-ids.txt`、欠落した `container-stop-status.txt` がある。gate が要求する `stop_exit_code=0` と `container_running=false` を記録できず、workflow の失敗を招いた。

recorder の最終 report は archive finalized と記録し、motion archive も完全で 8 window に両チームの移動がある。試合結果の MaximumTimeReached は別 Issue #54 の POST_GAME 条件であり、#53 に追加しない。

修正として、MATCH cleanup では AppHost shutdown の前に、事前 container snapshot と当該 run の owner/stack/resource/run label を照合して AutoRef container を限定し、停止状態を記録する。AutoRef の通信動作は変えない。修正後の CI と MATCH 受入はまだ未実施。

## 残件

- AutoRef native log の VisionTracker 0 件は、AutoRef 自身が 11010 を受信した件数ではない。Issue 条件の送信要件は observer の source attribution で確認できるが、AutoRef 内部の追加受信要件が承認済み設計に適用される場合は別途確認が必要。
- Duck の非送信は runtime 設定と空の self-source list で裏付けられている。raw UDP 全体の非送信証明ではない。
- cleanup 順序の修正後に通常 CI と一度の Linux MATCH で archive gate を再確認する。
