The existing model test enumerated IHostedService order: OrchestratorHostService is 12th and ContainerIdentityHandoffService 13th. No AppHost/DCP was started by that enumeration test.
Current Program dependency direction: GC.WaitFor(Duck); Duck.WaitForStart(simulator). The hypothesized cycle is conditional on Duck strict health requiring the handoff: DCP waits for resources to become ready before OrchestratorHostService.StartAsync completes; ordinary StartAsync for the later handoff service then cannot run. The fix uses IHostedLifecycleService.StartingAsync (the .NET host lifecycle phase before hosted service StartAsync) and preserves both WaitFor dependencies. Fixed runtime test verifies the same handoff worker can process a resource event while a preceding DCP-like hosted service is blocked in StartAsync. This establishes the lifecycle mechanism in a test, not a real DCP runtime measurement.
