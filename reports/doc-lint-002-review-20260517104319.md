# DOC-LINT-002 レビュー

## 対象

- IbisDuck の SudachiPy 依存、`npm` 実行名、文書、進捗管理、許可一覧更新
- CodexSkill の `review-enforcer` 共有スクリプト追加

## レビュー結果

阻害指摘あり。SudachiPy 版 checker の `--stdin` が従来版の対象範囲を壊しており、標準入力で渡した 1 文書だけを確認できない。

- 重大度: High
- 対象: `/home/ibis/AI/CodexSkill/skills/review-enforcer/scripts/check-markdown-whitelist-sudachi.py:207`
- 内容: `read_inputs()` が `--stdin` の通常文書入力でも `read_whitelist_description_inputs(whitelist.entries)` を追加している。従来版は `--stdin` 通常文書では標準入力本文だけを検査しており、`printf 'SudachiPy\n' | npm run lint:md:whitelist:legacy -- --stdin tools/lint/README.md --list-unknown` は成功する。一方、SudachiPy 版は同じ入力でも既存 whitelist description の未登録漢字語を大量に拾って失敗するため、`--stdin` の focused gate として使えない。

上記以外に、レビュー範囲内で正常系を直接止める阻害指摘は確認しなかった。

## 指摘

### High: `--stdin` が入力本文以外の whitelist description まで検査して失敗する

- ファイル/行: `/home/ibis/AI/CodexSkill/skills/review-enforcer/scripts/check-markdown-whitelist-sudachi.py:207`
- 根拠: `--stdin` 指定時、whitelist ファイル自身ではない通常文書入力に対して `[(normalized_stdin_path, stdin_text or ""), *read_whitelist_description_inputs(whitelist.entries)]` を返している。
- 影響: `--stdin` はエディタ連携や差分本文の focused check として、渡された本文だけを検査できる必要がある。現状では本文が許可語だけでも、既存 whitelist description 側の未登録漢字語で失敗する。
- 再現:
  - `printf 'SudachiPy\n' | npm run lint:md:whitelist:legacy -- --stdin tools/lint/README.md --list-unknown` は exit code 0。
  - `. .codex-doc-lint-venv/bin/activate && printf 'SudachiPy\n' | npm run lint:md:whitelist -- --stdin tools/lint/README.md --list-unknown` は exit code 1。出力は `tools/lint/markdown-whitelist.yaml:* [whitelist description]` 由来の未知語を大量に含む。
- 期待: 通常文書の `--stdin` は標準入力本文だけを検査する。whitelist ファイルを `--stdin tools/lint/markdown-whitelist.yaml` として渡した場合だけ、whitelist value/description を検査する。

### 注意: Python 依存は通常 `lint:md` の必須前提になっている

- ファイル/行: `/home/ibis/ssl/IbisDuck/package.json:7`, `/home/ibis/ssl/IbisDuck/package.json:11`, `/home/ibis/ssl/IbisDuck/tools/lint/README.md:13`
- 内容: `lint:md` は `lint:md:whitelist` を常に実行し、`lint:md:whitelist` は SudachiPy 版 Python スクリプトへ切り替わっている。README は Python 依存を「SudachiPy を使う語彙抽出と許可一覧検査を使う場合」と説明しており、実質的には標準 lint gate の必須準備である点が少し弱い。
- 影響: 依存未導入時は案内付きで exit code 2 になるため動作不能ではないが、運用手順としては `npm install` だけでは標準 `npm run lint:md` が走らなくなったことを明示した方がよい。

### 確認済みの非指摘事項

- `extract-markdown-vocabulary-sudachi.py` は `.md` / `.txt`、`--files`、`--changed`、頻度集計、出現元、`groupKey`、TSV/JSON 出力を実装している。
- Markdown noise 除外は fenced code、inline code、脚注定義、URL、mailto、HTML コメント、参照リンクアドレス、inline link アドレスを対象にしており、見えるリンク文字列は残す実装になっている。
- whitelist checker は `term` / `description` 必須、`aliases` 正規化、description 検査、`--files`、`--changed`、`--stdin`、`--list-unknown` の入口を持つ。ただし `--stdin` の通常文書対象範囲だけ上記阻害あり。
- whitelist 追加は `SudachiPy`、`Python`、`JavaScript`、`Markdown`、`リンク` の 5 件で、大量追加ではない。`tools/lint/prh.yml` は `rules: []` で、意図しない表記統一規則の追加は見当たらない。
- `lint:md:vocab -- --changed` は変更中の `tools/lint/README.md`、`Tracker/Design/phases-status.md`、`Tracker/Design/tasks-status.md` を対象に頻度降順の語彙一覧を出力した。

### 未解消リスク

- `npm run lint:md:whitelist` と全体 `npm run lint:md` は、漢字語も検出する方針により現行 whitelist では意図的に失敗状態である。これは実装報告にも記録されているが、標準 lint gate として使うには whitelist 再構築と利用者の明示確認が別途必要。
- `namespace` / `ネームスペース` / `名前空間` のような英日意味対応は自動確定しない方針であり、現実装の `groupKey` は読みまたは正規形ベースの候補グルーピングに留まる。意味対応の最終判断は利用者確認が必要。
- `.codex-doc-lint-venv/` を検証用に作成した。`.gitignore` 対象であり、記録対象には含めない。
