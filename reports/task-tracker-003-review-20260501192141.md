## 指摘事項

- 指摘要約または「指摘なし」:
  - High: `0..N CommittedFrames` を固定するはずのテストが件数しか見ておらず、どの frame が flush されたかを拘束していません。`Update_CanReturnZeroFramesWhileBuffering_AndMultipleFramesWhenSeveralGroupsFlush` は 3 回目の `Update` で `CommittedFrames.Count == 2` だけを確認しているため、実装が中間 frame を落として `1.0s` と `3.0s` を返したり、同一 frame を重複返却しても通ってしまいます。これは「中間 frame を捨てない」「古い順に全件処理する」という時系列契約を固定できていません。参照: `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:81-112`, `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:268-269`, `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:967`
  - Medium: late packet テストが「その場で空結果かつ diagnostics が 1 増える」ことしか見ておらず、捨てたはずの packet が後続 flush に混入しないことを保証していません。現状の `Update_DropsLatePacketsAndRecordsDiagnostics` だと、実装が diagnostics を加算したうえで内部 buffer や state を誤って汚染しても検出できません。`late packet は状態更新に使わない` という契約を固定するには、後続 `Update` 後の `CommittedFrames` に `frameNumber: 11` / `x:150` 相当が現れないことまで確認すべきです。参照: `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:115-146`, `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:358`
  - Medium: profile switch 周りの時系列契約が event kind の並びだけに縮退しており、reset 後も `frame_number` が継続することを固定できていません。今回の suite にある profile switch テストは control-only で `ProfileSwitched` だけが出ることと、同一 result で `ProfileSwitched` が `WorldFrameCommitted` より前に並ぶことしか見ていないため、実装が profile 切替時に frame counter を巻き戻しても通ります。設計は `frame_number` 継続を明示しているので、少なくとも切替前後で committed frame の番号が単調増加のままであることを追加で固定すべきです。参照: `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:188-219`, `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:596`, `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:965`
  - Low: tracking は `tasks-status.md` で `TRACKER-003` を「engine の時系列契約テスト追加」として done に進めていますが、同じ workspace context の設計書末尾にはまだ `TRACKER-003: TrackerEngine の初期実装` という旧 breakdown が残っています。commit メッセージで tracking files を同期したとしているのに、この task-to-design 対応が食い違ったままなので、後続 task の読み手が `TRACKER-003` の完了内容を誤解しやすい状態です。参照: `Tracker/Tracker.Core/Design/tasks-status.md:23`, `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:980-988`

## 結果

- 結果:
  - 指摘 4 件。内訳は High 1 件、Medium 2 件、Low 1 件
  - 主問題は、`TRACKER-003` の中核である engine 時系列契約テストが `0..N CommittedFrames`、late packet 隔離、profile switch 後の frame continuity を十分に固定していないこと
  - 現状のまま `TRACKER-003` を完了扱いにすると、後続の `TRACKER-006` / `TRACKER-007` 実装で時系列バグが残ってもテストが通る余地がある
  - tracking についても設計書側の task breakdown が未同期で、`TRACKER-003` の意味づけに不整合が残る

## リスク

- 未解決のリスクまたは後続対応:
  - multi-frame flush の identity/order が未固定なままだと、engine が中間 frame を落としても contracts フェーズで検出できない
  - late packet の state 汚染が未検出だと、reorder 実装後に古い観測が後から world frame へ混入する退行を見逃す
  - profile switch 時の `frame_number` continuity 未固定のまま進むと、observer や official packet 側で単調増加前提を破る実装が入りうる
  - 設計書末尾の旧 task breakdown を放置すると、以後の dedicated review や進捗同期で task scope の誤読が再発しうる
