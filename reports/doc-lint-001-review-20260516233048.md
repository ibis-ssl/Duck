# DOC-LINT-001 review

## Scope

- IbisDuck Markdown lint wiring, repository whitelist / target config, setup memo, tracking, and implementation report.
- CodexSkill `review-enforcer` shared Markdown lint scripts and review gate documentation used by IbisDuck through `.agents/skills`.

## Reviewer

- Dedicated sub-agent review: `019e312a-7117-7843-8128-62f933a27c44`
- Reviewer model: `gpt-5.4 high`

## Criteria

- Shared lint implementation lives in CodexSkill `review-enforcer/scripts/`.
- Each repository owns its own `tools/lint/markdown-whitelist.yaml` and `tools/lint/markdown-targets.json`.
- Whitelist entries require `term` and `description`; aliases can allow hyphen and space forms without allowing component words by themselves.
- Whitelist descriptions are lint targets.
- Backtick / fenced code are excluded, but backtick or quote based lint evasion is review-blocking.
- Direct file mode exists for focused validation.
- User-editable Markdown is in scope except dependency, build output, vendored reference, and explicit opt-out paths.
- Current full Markdown lint failure is acceptable only as an intentionally failing stricter gate.

## Findings

Initial review found two issues:

- High: direct-file / changed-file mode did not apply `ignoreDirectories`, allowing dependency or build Markdown paths to be targeted directly.
- Medium: the README direct-file `textlint` example used bare `textlint`, which is not available outside npm script PATH injection.

## Disposition

- Fixed High: shared target listing and whitelist checking now use the same `isIgnored()` logic for full, changed, and explicit-file modes. `ignoredPrefixes` and `ignoreDirectories` are both applied.
- Fixed Medium: README direct-file `textlint` example now uses `./node_modules/.bin/textlint`.
- Re-review: no findings.
