# ASPIRE-006B implementation plan

Issue #39 is implemented as a single PR stacked on `design/issue18-aspire-test-orchestration` at reviewed base `067f93b4eb137912d55c7f61f93414f80761e553`. PR #62 already supplies live comparison source readiness, fresh-packet checks, and UUID collision checks. This task will close the remaining acceptance gaps and confirm the complete Issue #39 scope.

## Planned scope

- Resolve the Duck, TIGERs, and ER-Force logical roles from tracker source metadata.
- Preserve UUID-preferred identity and explicitly verify endpoint fallback when UUID is absent.
- Keep sources with the same UUID distinct by endpoint where that is the defined identity, and make ambiguous role/identity collisions not Ready.
- Provide one resolver contract to live comparison readiness and replay of saved tracker snapshots, without changing generic diagnostics replay source aggregation.
- Add focused tests for the resolver, live readiness, and replay integration.
- Run the applicable Linux `ASPIRE-NET-003` through `ASPIRE-NET-005` acceptance and retain its diagnostics and results.

## Acceptance conditions

- Focused tests establish role mapping, UUID-preferred and UUID-absent endpoint fallback identities, and not-Ready outcomes for ambiguous collisions.
- The same role and source identity are resolved from equivalent live and saved source metadata.
- `ASPIRE-NET-003`: RuntimeHost and DebugHost both receive the `224.5.23.2:10020` stream during one observation window.
- `ASPIRE-NET-004`: TIGERs and ER-Force receive that stream and produce tracker output.
- `ASPIRE-NET-005`: DebugHost receives TIGERs and ER-Force tracker packets on `224.5.23.2:11010` as distinct sources.
- Exact-head validation results and required failure diagnostics are recorded in the PR.

## Not included
