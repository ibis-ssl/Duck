## 指摘事項

- 指摘要約または「指摘なし」:
  - 中: `Tracker/Tracker.Core/TrackerExecutionContracts.cs:203` は event time を常に `TCapture` から算出しており、設計で要求されている `TCapture` 欠落時または `0` 以下時の `TSent` フォールバックがありません（`Tracker/Tracker.Core/Design/tracker-architecture-plan.md:163-164`, `353-355`）。`SSL-Vision` 側で `TCapture` が未設定の packet を受けると `0ns` が reorder buffer に入り、即時 flush や late packet 判定の誤動作を起こします。TRACKER-006 の event-time 契約そのものに関わるため、このままでは仕様未達です。
  - 低: `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:173-200` の新規テスト `Update_EmitsWorldFrameCommittedForEachCommittedFrameInFlushOrder` は、名前に反して複数 frame が同一 `TrackerUpdateResult` で flush される状況を作れていません。`reorderWindowNs: 0` では各 `Update` で最大 1 frame しか commit されないため、実装が「1 update あたり 1 件しか `WorldFrameCommitted` を emit しない」形に壊れてもこのテストは通ります。multi-frame flush 時の event 件数と順序を直接検証するケースに直した方がよいです。

## 結果

- 結果:
  - FAIL。`TRACKER-006` の reorder buffer / flush pipeline 実装と関連 contract-test 更新を確認した結果、event-time フォールバックの仕様漏れ 1 件と、追加テストの検証不足 1 件を確認した。修正と再レビューが必要。

  - 現在の追加テストのままでは、multi-frame flush 時の `WorldFrameCommitted` 件数・順序 regressions を将来取り逃がす。
