# TRACKER-039 証跡

## 対象

- diagnostics log: `Tracker/Tracker.Server/bin/Debug/net10.0/packet-captures/ssl-vision-packets-20260511T133110654Z-b94338b955704b8bb195e7d60bc7f68c.tracker-diagnostics.log`
- capture: `Tracker/Tracker.Server/bin/Debug/net10.0/packet-captures/ssl-vision-packets-20260511T133110654Z-b94338b955704b8bb195e7d60bc7f68c.jsonl.gz`
- render snapshot: `Tracker/Tracker.Server/bin/Debug/net10.0/packet-captures/ssl-vision-packets-20260511T133110654Z-b94338b955704b8bb195e7d60bc7f68c.render-snapshots.jsonl.gz`
- user selected frame: `trackedFrame=3448` 付近

## 観測

旧 render snapshot では `trackedFrame=3439` で青1番が `x=2841,y=-4310,o=0.011` へ瞬間移動し、同じ frame に青11番が `x=5540,y=-4307,o=0.003` として現れていた。

同 frame の raw detection では青1番 / 青11番が `x=5540,y=-4309` 近傍に重複し、さらに青1番が `x=2841,y=-4310` にも現れていた。これは表示処理ではなく、merge window 内の同一 camera / team / robot id 候補を後続 detection が上書きし、robot id の突然の入れ替わりを位置ズレより低確率として扱っていなかったことが原因。

## 修正

- merge window 内で同一 camera / team / robot id の候補が複数ある場合、既存同一 ID track 近傍の候補を優先する。
- 既存別 ID track 近傍に突然現れる別 robot id 候補は `RobotTracker.IdentitySwitchDistanceMm` の範囲で抑制する。
- `IdentitySwitchDistanceMm` を `TrackerRobotTrackerOverrides`、`Tracker.Server/appsettings.json`、configuration resolver / cloner / comparer、`Tracker.CaptureReplay` settings reader、README に外出しした。
- `Tracker.CaptureReplay` に `--max-detail-robots` を追加し、detail 出力で後続 robot まで確認できるようにした。

## 検証

1. 実装差分を `git stash push -m tracker-039-verify-tracked` で退避し、旧実装へ戻した。
