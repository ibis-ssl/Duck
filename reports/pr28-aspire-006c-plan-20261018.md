## Issue / 設計の受入条件

Issue #40 本文と `Tracker/Design/Testing/tracker-comparison-debug-design.md` を基準に、次を focused test で固定する。

1. robot は team color と robot id の組で対応させる。同じ robot の位置・速度・角度・角速度差を定義し、片側だけの robot は missing として返す。
2. ball track id は cross-tracker identity に使わない。有限な XY 座標かつ距離が inclusive gate 以下の edge だけを候補にする。対応数最大、距離合計最小、最後に `(reference index, comparison index)` 辞書順最小の優先順で一対一対応させ、残りは unmatched とする。
3. ball / robot の数値差は matched object に対して定義し、missing / unmatched object をゼロ差として扱わない。

## 実装・検証順序

1. 専用 worktree の既存モデルとテスト配置を確認し、39 に依存しない入力・出力契約を絞る。
2. focused test を先に追加し、未実装状態で期待どおり失敗することをローカル確認する。失敗中は push しない。
3. 最小の照合／差分実装を加え、focused test と関連回帰を通す。
4. `git diff --check` と対象プロジェクト build/test を成功させる。
5. 成功した意味のある実装単位ごとに通常 commit / push する。force push、merge、deploy、branch 削除は行わない。
6. PR の変更後 HEAD を push し、exact-head CI を確認して結果と残る39依存を記録する。独立最終レビューは親担当に委ねる。
