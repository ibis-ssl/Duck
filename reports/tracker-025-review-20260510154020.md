## Findings

- Medium: `Tracker/Tracker.Server/appsettings.json:24,67-69` で `ActiveProfileName` を `default` から `sim` に変更したため、サーバー起動直後の publish 先が `Tracker:Profiles:default:Publish:Port = 10010` ではなく `Tracker:Profiles:sim:Publish:Port = 11010` へ切り替わります。今回のタスクは tracker algorithm 初期値の Tigers 寄せと stale track 抑制ですが、この変更は初期 runtime profile と multicast 契約まで変えてしまいます。既存の consumer が 10010 を前提にしている場合、TRACKER-025 適用後に tracked 出力を受け取れなくなります。
- Low: `Tracker/Tracker.Tests/TrackerConfigurationBindingTests.cs:11-140` は in-memory の `simulation` プロファイルだけを検証しており、実際に出荷される `Tracker/Tracker.Server/appsettings.json` を読んでいません。今回追加した Tigers 由来の既定値 (`0.462756`, `0.05`, `1000000000`) や `ActiveProfileName` のような本番設定の drift を検知できず、上記の startup profile 回帰もテストでは捕まりません。

## 所見の処置

- Medium: 保留扱い。`ActiveProfileName = sim` と `sim` profile 追加は TRACKER-025 実装前からユーザー指定の実行状態として存在した差分であり、今回の stale track 抑制変更では戻さない。今回追加した実 `appsettings.json` regression test で `sim` 起動と port `11010` を明示的に固定し、暗黙 drift ではなく意図したローカル設定として扱う。
- Low: 対応済み。`TrackerConfigurationBindingTests.AppsettingsJson_ExposesTigersAlignedTrackerDefaults` を追加し、実 `Tracker.Server/appsettings.json` から `default` / `sim` / `fast` の Tigers 寄せ tracker 値、`ActiveProfileName`、解決後 publish port を検証するようにした。

## 最終結果

- Findings への処置完了。`ActiveProfileName = sim` は既存のユーザー指定設定として保持し、実 appsettings regression test を追加した。再検証で `TrackerConfigurationBindingTests` 4 件および全体 104 件が通過したため、TRACKER-025 はレビュー後続対応済み。
- Re-review: 指摘なし。follow-up で追加された `TrackerConfigurationBindingTests.AppsettingsJson_ExposesTigersAlignedTrackerDefaults` は実 `Tracker/Tracker.Server/appsettings.json` を読み、`ActiveProfileName = sim`、`default/sim/fast` の profile 値、解決後 publish port `11010` を固定しているため、初回指摘の `appsettings.json` drift 検知欠落は解消されている。`ActiveProfileName = sim` を user-requested local runtime setting として扱う disposition も、この regression test で明示的に裏づけられており、TRACKER-025 の follow-up に blocking finding は残らない。
