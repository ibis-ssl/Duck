## 結果

- 結果:
  - README は `Tracker.CaptureReplay` CLI を削除せず、agent / 自動検証 / regression 調査用の補助経路として残し、通常ユーザー確認は `/diagnostics` の `Tracker Comparison` panel を主経路と説明している。
  - `/diagnostics` の説明は、実装の `TrackerDiagnosticsComparisonSourceFilterKind` と UI option にある `All` / `External` / `Own` / `Unknown` / source label filter と一致している。
  - comparison panel に残す項目は、実 UI の `Status`、`Records`、`Skipped`、`Errors`、`Selected frame`、`Selected time`、`Entry status`、`Rule`、`Source role`、`Source label`、`Snapshot frame`、`Own timestamp ns`、`Nearest timestamp ns`、`Delta ns`、`Balls`、`Robots`、`Raw payload` と一致している。
  - sidecar status の説明は実装 enum の `NoLogSelected`、`MetadataMissing`、`MetadataCorrupt`、`SnapshotMetadataMissing`、`SidecarNotCreated`、`SidecarPathMissing`、`SidecarMissing`、`SidecarEmpty`、`SidecarCorrupt`、`Ready` と矛盾しない。
  - `RecordCount`、`SkippedRecordCount`、`ErrorCount`、record 0 / sidecar empty の読み方は metadata / view-state の count 表示と一致している。
  - manual evidence に残す selected frame / selected time、source filter、sidecar status、record / skipped / error count、entry status、source role / label、snapshot frame、own timestamp ns、nearest timestamp ns、delta ns、balls / robots、raw payload restored 表示が明記されている。
  - README の CLI comparison 説明は `trackerSnapshot ... rawPayloadRestored=True` と `trackerComparison ... rule=nearest-timestamp ...` を残し、UI 主経路と CLI 補助経路の位置づけが明確。
  - docs-only 差分であり、review 対象に production / test code の変更はないため、`dotnet test` 未実行の判断は妥当。`git diff --check` は成功。

## リスク

- 未解決のリスクまたは後続対応:
  - 実ブラウザでの manual evidence 採取は `TRACKER-053` の PR ready / final evidence 側に残るが、今回の docs-only review の blocking finding ではない。
  - `Tracker:Receive` は起動時設定で live receiver を登録するため、manual evidence では `Tracker:Receive:Enabled=true` と監視対象 endpoint を起動前に揃える前提になる。README はこの前提を説明しており、追加修正は不要。
