# PR #63 文書lint追跡記録（2026-10-05）

## 対象と修正

PR #63 が更新した設計書と作業台帳を全文で再検査した。設計書の先頭に混入していた `Warning: truncated output ...` と `Total output lines: 519` の2行および空行を削除した。混入は表示用出力のメタデータであり、設計本文ではない。作業台帳には内容差分を加えていない。

## 検査結果

対象:

- `Tracker/Design/Testing/aspire-simulation-test-environment.md`
- `Tracker/Design/tasks-status.md`

textlint は両ファイルとも成功した。cspell は2ファイルで200件を報告した。SudachiPy whitelist 検査では設計書2,485件、作業台帳622件、計3,107件の違反を報告した。正規化後の異なる語は434語で、内訳は英字語1,795件、カタカナ語1,312件だった。これらの件数は、冒頭メタデータを含む `236eb38` の同じ検査結果と比べ、設計書で16件減少した。作業台帳の件数は変わらない。

主な違反は、一般技術語（`resource`、`packet`、`mode`、`host`、`readiness` など）とそのカタカナ表記（「リソース」「パケット」「モード」「ホスト」など）である。ほかに製品・OS・プロジェクト名（`Aspire`、`Crane`、`Docker`、`Linux`、`Windows`、`TIGERs` など）も含む。一般語を多数含むため、残件を固有名詞としてまとめて扱うことはできない。

## 判定

メタデータ削除後も、設計書・台帳の全文に対するcspellおよびwhitelist検査は成功していない。whitelistや検査設定は変更していない。大量の用語を機械的に置換すると、技術上の意味や日本語の文意を損なうことを確認したため、その置換結果は採用しなかった。今回の差分で追加した文章は、前回の差分単位のlint検査でtextlint、cspell、whitelistの指摘がなかった。

全文の残違反を解消するには、一般技術語の用語選定を含む文書全体の意味レビューが必要である。本記録は全文lintが完了したことを示すものではない。
