## 指摘事項

- [Medium] `Tracker/Tracker.Core/Engine/TrackerEngine/Settings.cs:174` と `Tracker/Tracker.Core/Engine/TrackerEngine/Settings.cs:183` で orientation 用の measurement variance / process variance が hardcode され、`RobotTracking.cs:207`、`RobotTracking.cs:238`、`RobotTracking.cs:295` からも profile の `MeasurementNoiseVarianceScale` / `KalmanProcessNoiseScale` / `KalmanInitialVelocityVariance` を通らなくなっている。`Tracker/Tracker.Core/Design/tracker-architecture-plan.md:697` と `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:698` は、`ProcessNoise` / `MeasurementNoise` と Kalman scale 系設定を profile ごとの外部 tuning として、停止時の揺れと追従性を code 変更なしで調整できる契約にしている。今回の修正目的である「mm 用 covariance を rad 軸に流用しない」は満たしているが、rad 単位の基準値を使ったうえで既存 scale を掛ける、または設計・設定契約を明示的に変更する必要がある。現状のままだと、diagnostics log で別 capture や実機条件に合わせて orientation jitter / angular velocity clamp 周辺を profile で調整できず、設計と実装が矛盾する。

## 結果

- blocking finding 1 件。focused test は 22 passed、full test は 151 passed を確認した。
- raw Vision / camera merge / display ではなく orientation filter に原因を切り分ける方針、rad 単位 covariance への分離、`Tracker.CaptureReplay` の `frame` detail filter と robot `o` / `w` 出力、diagnostics log の tracked robot `o` / `w` 出力は概ね task 目的に沿っている。
- ただし orientation Kalman tuning が既存 profile scale 契約から外れているため、TRACKER-038 はこの finding の解消または設計変更が必要。
- 実行形態は、依頼文の「nested Codex、codex exec、別 sub-agent 起動は禁止」に従い、別 agent は起動せず reviewer として repository を直接確認した。

## リスク

- angular velocity clamp の固定値 `2π rad/s` が正常な高速回転追従をどこまで許容するかは、現 test では低速回転と停止 jitter 中心にしか固定されていない。上記 finding と合わせて、profile tuning 契約を維持する場合は scale 反映と高めの正常回転ケースを追加して確認する必要がある。
- `Tracker.CaptureReplay` を test project から参照するための `InternalsVisibleTo` / project reference 追加は focused/full test では通っているが、CLI の publish / packaging まではこの review では実行していない。
