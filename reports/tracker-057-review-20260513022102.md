## 指摘事項

- 指摘要約または「指摘なし」:
  - Blocking finding: なし。
  - Held concern: `Tracker/Tracker.Server/Tracking/TrackerDiagnosticsComparisonUiState.cs:158` の `CreateOverlayLayerSources()` は左右 selector が同じ source の場合も常に `Layer A` / `Layer B` の 2 layer を返す。`DiagnosticsFieldOverlayRenderModelFactory.Create(...)` はそのまま全 layer を作り、`DiagnosticsFieldOverlayCanvas.razor:69` 以降は両方 visible なら同一 source の drawable を二重描画する。設計 `Tracker/Tracker.Core/Design/tracker-server-cli-ui-detail-design.md:179` は「左右が同じ source の場合は 1 layer として扱い、legend に同一 source であることを表示する」としているため、同一 source 選択時の表示は設計と一致しない。通常の 2 source overlay は成立しており、片 layer を非表示にすれば回避可能なため blocker にはしないが、同一 source case を done 条件に含めるなら追加修正と focused test が必要。

## 結果

- 結果:
  - TRACKER-057 の未コミット差分を対象に code review を実施した。
  - 既定 `Split` は維持され、`Overlay` は `comparisonUiState.FieldDisplayMode` による分岐で既存左右 Field 表示とは別 path になっていることを確認した。
  - Field source option に `All` を追加せず、Overlay は既存の左 Field source selector を `Layer A`、右 Field source selector を `Layer B` として使っていることを確認した。
  - visibility state は `TrackerDiagnosticsComparisonUiState` に保持され、`ResetForLogChange()` でのみ既定復帰し、selected entry / source 変更や overlay 操作では維持される contract を focused test で確認した。
  - tracker source layer は `LoadFieldSourceFrame(...)` と cached index を再利用し、overlay mode / visibility 操作で sidecar JSONL 全体再読込へ戻っていないことを確認した。
  - render snapshot geometry がない場合は overlay model の `Geometry` を null にして empty state を返し、sidecar から geometry を復元しないことを確認した。
  - 片方 missing でも ready layer の drawable objects は model に残ること、legend には status / nearest delta / drawable count が null missing 時にも `-` または status text として表示されることを確認した。
  - `DiagnosticsFieldViewFactoryTests` により、TRACKER-056 review の held concern だった semantic summary mapper の ball / yellow / blue 変換が直接固定されたことを確認した。
  - `VisionBallMarker` / `VisionRobotMarker` の styling extension は default 値が既存 stroke / style null のため、single source Field の既定表示を変えないことを確認した。
  - `git diff --check` は問題なし。
  - focused test は 43 passed。
