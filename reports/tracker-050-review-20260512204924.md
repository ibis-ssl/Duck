## 指摘事項

- High / Blocking normal-path problem: `TrackerDiagnosticsComparisonViewStateReader.Load` の `selectedEntryIndex` contract が既存 diagnostics UI の選択 index と一致しない。reader は `ReadDiagnosticsEntries(diagnosticsLogPath)` で diagnostics log 全体を読み直し、`entries[selectedEntryIndex]` を選択行として扱う（`Tracker/Tracker.Server/Tracking/TrackerDiagnosticsComparisonViewStateReader.cs:227`, `Tracker/Tracker.Server/Tracking/TrackerDiagnosticsComparisonViewStateReader.cs:234`）。一方、既存 UI は `TrackerDiagnosticsLogReader.ReadFile` の結果だけを `entries` に入れ、`SelectedEntryIndex` はその表示済み list 内 index である（`Tracker/Tracker.Server/Components/Pages/Diagnostics.razor.cs:39`, `Tracker/Tracker.Server/Components/Pages/Diagnostics.razor.cs:110`, `Tracker/Tracker.Server/Components/Pages/Diagnostics.razor.cs:166`）。`TrackerDiagnosticsLogReader.ReadFile` は 10,000 件を超えた場合に先頭側を omit して末尾だけ返す（`Tracker/Tracker.Server/Tracking/TrackerDiagnosticsLogReader.cs:94`, `Tracker/Tracker.Server/Tracking/TrackerDiagnosticsLogReader.cs:102`）。そのため長い diagnostics log で UI の先頭表示行を選ぶと、comparison reader は full file の 0 行目を比較してしまい、選択中 diagnostics entry に対応する ibis own snapshot timestamp ではなく別 entry の nearest summary を silent に返す。`TRACKER-050` の selected entry comparison contract と、後続 `TRACKER-051` の selected log / selected entry / playback tick 同期 normal path を壊すため、line number、tracked frame、または omitted offset を含む contract へ修正が必要。
