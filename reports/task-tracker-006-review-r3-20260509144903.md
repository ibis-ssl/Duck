## 指摘事項

- 指摘要約: high 2 件
- High: `Tracker/Tracker.Core/TrackerExecutionContracts.cs:77-116` は flush 対象を `EventTimestampNs <= maxSeenDetectionTimestampNs - ReorderWindowNs` で個別選別してから group 化しているため、anchor が cutoff を越えた時点で同一 `MergeWindow` 内の後続観測がすでに `pendingDetections` に存在していても先頭観測だけを先に commit できます。たとえば `(1.000, 1.015, 1.060)` / `ReorderWindow=50ms` / `MergeWindow=20ms` では 3 件目到着時に `1.000` が単独 frame 化され、設計書の「`ReorderWindow` を越えた detection group を flush」「anchor event time から `MergeWindow` 以内の camera-local state を同一 world frame に使う」契約 (`Tracker/Tracker.Core/Design/tracker-architecture-plan.md:355,372`) を破ります。
- High: `Tracker/Tracker.Core/TrackerExecutionContracts.cs:41-52,133-145,194` の late packet cutoff は `lastCommittedDetectionTimestampNs` までしか見ていないため、既に commit 済み group の末尾より後だが anchor `+ MergeWindow` 以内の packet を drop できません。commit 済み `[1.000, 1.015]` に対する `1.018` のような packet は本来 late 扱いで捨てるべきですが、現状は受理されて別 frame 化されます。追加テスト `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:236-287` は `1.010` しか検証しておらず、実際に壊れる `(latestCommitted, anchor+MergeWindow]` の帯域を捕まえられていません。
