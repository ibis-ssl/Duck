`phases-status.md` は現在のタスクを `TRACKER-031` としている一方、`tasks-status.md` の `## 現在のタスク` は `TRACKER-030` / `done` のままです。同じファイル内の `## 次の調査タスク` とタスク一覧では `TRACKER-031` / `in_progress` と記録されているため、Tracker の canonical tracking file として実状態が一貫していません。

## 確認結果

- `TrackerExecutionContracts.cs` の outlier 抑制は、同じ `team + robot id` に複数 camera 観測がある場合だけ作動し、既存 camera-local track の予測位置に近い観測を anchor としている。anchor から movement gate より遠い観測だけが除外されるため、今回の「正常観測が別 camera にある遠方 outlier を merge に混ぜない」目的に合っている。
- 単一観測では `DropFarRobotOutliersWhenSameRobotHasNearObservation` がその観測をそのまま残すため、単一 camera の大きな移動と既存 outlier reset 契約は維持されている。全 camera 観測が既存 track から遠い場合も従来どおり全観測を残す分岐になっている。
- regression test には、別 camera の正常な同一 robot ID 観測がある場合に遠方誤 ID 観測で merged robot が瞬間移動しないことを確認する日本語コメントがある。
- evidence report は、原因、変更内容、修正前 failure、focused regression、capture replay、full tests を記録しており、ユーザー提示の検証結果と一致している。

## 結果
