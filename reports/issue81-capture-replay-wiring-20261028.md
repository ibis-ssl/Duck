# 課題81: 記録と再生のコンテナ配線

対象は PR #84 の I81-08A。起点は `362363d011cabecf32f321725370a59663e39676`、公開先は既存の `task/issue81-aspire-desktop-bridge` である。実装の確認用コミットとして公開し、通常レビューと文書検査は継続する。課題全体の完了ではない。

## 1. 変更前の問題

DebugHostには記録と再生の機能があるが、比較構成の記録先をホストへ保存する割当てが無かった。後日の読み取り専用再生を選ぶ構成も無かった。

## 2. 今回の変更

比較構成では実行別のホスト保存先を `/data/captures` へ読み書き可能で割り当てる。既存の記録先を自動で再利用せず、安全な実行IDと絶対パスを確認する。通常停止やコンテナの再作成で記録を削除しない。

`Testing:DebugHost:ReplayOnly=true` と `Testing:DebugHost:ReplayDirectoryPath` の明示指定ではDebugHostだけを登録し、既存保存先を `/data/replay` へ読み取り専用で割り当てる。他モードとの同時選択は拒否する。保存先の基準は既定の利用者別領域で、`Testing:DebugHost:CaptureRootPath` はその基準ディレクトリだけを変更する。

## 3. 動作の要点

再生専用時は記録開始を実行制御で拒否し、画面の記録ボタンも無効にする。DebugHost自身が矛盾する記録・追跡の設定を無効化し、視覚入力と追跡情報のUDP受信・送信を開始しない。通常の記録開始操作は維持する。

## 4. 対象外と残件

通常構成のcm4-simにはloopback宛先が残り、Craneの外部宛先と再作成契約も未確定である。simulatorとGame Controllerだけを別ネットワークへ置換して通常構成の完成とは扱わない。I81-07の該当統合はこの契約確認を残す。

固定デバッガーの供給調査は任意であり、この変更の前提にしない。実コンテナ起動、Windowsの保存先権限とブラウザー操作、課題全体の独立最終レビューは今回実施していない。課題82全体の受入を課題81の追加必須条件にはしない。

## 5. 検証

関連回帰87件が成功した。AppHostの構成全体、記録・再生の既存回帰、新しい保存先設定、記録開始の拒否と起動設定の保護を含む。AppHostとDebugHostの `dotnet build --no-restore -m:1 /nr:false` はともに成功した。AppHostは既知のASPIRE010警告1件、DebugHostは警告・エラー0である。

先行した再生専用構成の試験は、従来の5資源が登録されるため実行時に失敗した。新しい設定と制御のAPIについては未実装のためコンパイル時に失敗した。最初の成功確認では不正な実行IDの試験6件にアサーション誤りがあり、既に作成した親ディレクトリを検査していた箇所を訂正した。この失敗と、後続の名前空間参照のコンパイル失敗は保存しており、先行試験を無変更で全件通過したとは扱わない。

変更文書の検査は継続中である。変更断片5件の文章検査はすべて成功した。読みやすさ検査は4件成功、比較設計の断片1件は箇条書き比率により95点だった。これは断片の結果であり全文の点数ではない。許可語検査には用語の指摘が残り、綴り検査は検査断片の混入を除く確認が未完了である。入力文字コードによる検査器の失敗も履歴として残し、全文合格とは記録しない。証拠一覧は `evidence/issue81-capture-replay-wiring-20261028/verification.json` に置く。
