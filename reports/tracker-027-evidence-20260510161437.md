## 実装内容

### robot 近接重複 ID 抑制

同一 camera / team の raw robot detection を confidence 降順、robot id 昇順で採用し、既に採用済みの別 ID robot から `RobotRadiusMm * 1.5` 未満の候補は捨てるようにした。

これにより、再現ログの `Y1` と `Y11` のような同座標の近接重複では、同 confidence の場合に `Y1` が採用され `Y11` は tracked output に入らない。

review で、近接重複判定が committed group 全体に効いてしまう blocking finding が出たため、判定スコープを raw detection 単位の一時辞書に限定した。追加 regression test で、同一 camera の別 detection に現れた近接別 ID robot は落とさないことを固定した。

### ball 短命 secondary ghost 抑制

camera-local ball track に `ObservationCount` を追加した。primary 以外の secondary ball は、Tigers の `grownUpAge = 3` に合わせて 3 回以上観測された track だけを外部出力する。

また、前回 primary ball が今回も fresh observation として存在する場合は primary 候補として優先する。stale な前回 primary は優先しないため、新しい primary へ切り替わる既存契約は維持される。

## 契約テスト

追加・更新した観点:

- `Update_IgnoresCloseDuplicateRobotIdsFromSameCameraAndTeam`
  - Y1/Y11 のような同一 camera / team / 近接別 ID robot で低 ID 側だけが出力されること
- `Update_DoesNotApplyCloseDuplicateRobotFilterAcrossDetections`
  - 同一 committed group 内でも raw detection が異なれば近接別 ID robot を close duplicate として落とさないこと
- `Update_DoesNotEmitSingleFrameSecondaryBallGhost`
  - 既存 primary がある状態で 1 frame だけ入った secondary ghost が tracked output に増えないこと
- `Update_SelectsPrimaryBallByVisibilityAndStableSortsSecondaryBalls`
  - 継続観測された複数 ball は primary / secondary stable sort で出力されること
- `Update_DoesNotLetStaleBallTrackBridgeTwoFreshBalls`
  - 継続観測後も stale track が fresh ball の分離を壊さないこと
- `Update_KeepsNearbyDistinctBallsFromSameCameraSeparated`
  - genuine な近傍複数 ball は継続観測後に分離出力されること

## 設計書更新

`Tracker/Tracker.Core/Design/tracker-architecture-plan.md` に次を追記した。

- 同一 camera / team の近接別 ID robot を `Geometry.getBotRadius() * 1.5` 相当で拒否すること
- close duplicate robot の deterministic な採用順
- secondary ball は 3 回以上観測された grown-up track のみ外部出力すること
- previous primary は fresh observation の場合だけ primary 候補として優先すること
