## 指摘事項

- blocking normal-path problems:
  1. `TRACKER-013` が外出し対象として持っている tracking parameter の一部が、今回の blocker fix 後も runtime に反映されていません。設計では `RobotTracker` / `BallTracker` の process noise・measurement noise・gate、加えて近傍判定や visibility decay まで設定外出しする想定です（`Tracker/Tracker.Core/Design/tracker-architecture-plan.md:497-500`, `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:521-540`）。実際に resolver は `ProcessNoise` / `MeasurementNoise` / `Gate` を `TrackerEngineSettings` へ解決していますが（`Tracker/Tracker.Server/Tracking/TrackerConfigurationResolver.cs:40-64`）、engine 側で consumable になっている helper は `BallTracker.OutlierLimitMm` / `TrackLifetimeNs` と kick 系閾値だけです（`Tracker/Tracker.Core/TrackerExecutionContracts.cs:1477-1504`）。`TrackerRobotTrackerOverrides` / `TrackerBallTrackerOverrides` に残っている `ProcessNoise` / `MeasurementNoise` / `Gate` は定義されている一方（`Tracker/Tracker.Core/TrackerExecutionContracts.cs:1719-1740`）、今回の engine 実装にはそれらを参照する処理がありません。また visibility decay も依然として `Math.Pow(0.5d, deltaSeconds)` の固定値で、設定項目自体が存在しません（`Tracker/Tracker.Core/TrackerExecutionContracts.cs:1030-1039`, `Tracker/Tracker.Core/TrackerExecutionContracts.cs:1362-1372`, `Tracker/Tracker.Server/Tracking/TrackerOptions.cs:5-55`）。この状態では config 上で公開している tracking parameter を変更しても正常系の engine 挙動へ反映されず、`tasks-status` の exit criteria「tracker/network 設定が外部設定から束縛され、起動時設定が engine と publisher に反映される」（`Tracker/Tracker.Core/Design/tasks-status.md:33`）をまだ満たしません。
- user-confirmation-required gaps: なし。
- non-blocking held concerns:
  1. `ChipHeightThresholdMm` は engine に wiring されているものの（`Tracker/Tracker.Core/TrackerExecutionContracts.cs:1502-1504`）、今回追加された runtime behavior test は `RobotTracker.OutlierLimitMm` / `BallTracker.TrackLifetimeNs` / `KickDetector.ContactMarginMm` / `KickDetector.KickSpeedThresholdMmPerS` のみを直接検証しており（`Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:671-704`, `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:916-944`, `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:1248-1274`, `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:1350-1386`）、chip 判定閾値の回帰を捕まえる test はまだありません。コードは単純なので直ちに blocking とはしませんが、次回の変更で退行を見逃しやすい状態です。
- 指摘要約または「指摘なし」: blocking 1 件、held concern 1 件。前回 blocker の一部は解消されたが、`TRACKER-013` の設定外出し対象全体を見ると engine 反映はまだ部分的。

## 結果

- 結果: `fail`。対象 test 57 件は通過したが、レビュー観点では runtime wiring が `OutlierLimitMm` / `TrackLifetimeNs` / 一部 kick 閾値に限られており、設計と task exit criteria で要求されている tracking parameter 全体の設定反映は未完了のため、この task review は不合格。
