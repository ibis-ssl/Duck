## 指摘事項

### blocking normal-path problems

1. `Tracker/Tracker.Core/TrackerExecutionContracts.cs:1323-1370`
   `CollectCameraRobotObservations` は committed group 内の各 detection ごとに `AddRobotObservations` を呼んでいますが、近接重複判定に使う `observations` 辞書を detection 間で共有したままです。そのため `HasCloseRobotObservationWithDifferentId` は「同一 raw detection 内ですでに採用した robot」だけでなく、「同一 committed group の前の detection で採用した robot」まで参照してしまいます。merge/reorder window により同じ camera の連続 detection が 1 つの committed group に入った場合、前の detection にいた robot A の近くへ次の detection で別 ID robot B が現れただけで、同一 frame の重複ではない B まで落とし得ます。`reports/tracker-026-reproduction-analysis-20260510160509.md:64-68` と `Tracker/Tracker.Core/Design/tracker-architecture-plan.md:728-730` が求めているのは raw detection 単位の近接重複抑制なので、通常動線で genuine な robot を欠落させる回帰です。現行テスト `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:851-870` は 1 detection 内の Y1/Y11 ケースだけで、この group 越え誤抑制を検出できません。

re-review 追記:

- no blocking findings。`CollectCameraRobotObservations` は raw detection ごとの `detectionObservations` を使う形に修正され、close duplicate 判定は同一 detection 内に限定されたことを `Tracker/Tracker.Core/TrackerExecutionContracts.cs:1323-1342` で確認した。
- 追加テスト `Tracker/Tracker.Tests/Contracts/TrackerEngineTemporalContractTests.cs:873-909` は、同一 committed group 内でも raw detection が異なれば近接別 ID robot を両方保持することを固定しており、初回 blocking finding の回帰穴を塞いでいる。
