# RUNTIME-HOST-009 レビュー

## Blocking findings

1. `Tracker/Tracker.RuntimeHost/RuntimeTrackerConfigurationResolver.cs:17` から `:20`、`:50` から `:61` で、`Tracker:ActiveProfileName` が `Tracker:Profiles` に存在しない場合に `default` profile へ silently fallback している。DebugHost 側の `TrackerConfigurationResolver` は同じ状況を profile 名付き `InvalidOperationException` として失敗させる contract を持ち、既存 test `Tracker/Tracker.Tests/TrackerConfigurationBindingTests.cs:59` から `:72` でも固定されている。RuntimeHost は本番寄り headless normal path なので、active profile typo を起動時に検出せず、別 profile の publish 宛先 / engine 設定を使って `EngineSettings.ProfileName` だけ requested 名にする挙動は DebugHost 設定と矛盾し、official packet publish normal path を誤設定で成立させてしまう。`RuntimeTrackerConfigurationResolver` も missing active profile を明示失敗に揃える必要がある。

## Non-blocking findings

- Hold: latest packet buffer は設計どおり tick ごとに latest packet だけを消費する。`RuntimeVisionPacketBuffer.StorePacket` は clone した packet を単一 slot に上書きし、`TryTakeLatest` は未処理 latest を取り出して空にするため、tick 間の複数 packet は latest 優先になる。R009 の性能優先 normal path と design には合っており、queueing 必須とは判断しない。実機 cadence / drop の扱いは R010 manual evidence 後に必要なら判断する。該当箇所: `Tracker/Tracker.RuntimeHost/RuntimeVisionPacketBuffer.cs:14` から `:21`、`:24` から `:40`、`Tracker/Design/RuntimeHost/runtime-host-plan.md:108` から `:114`。

## 確認事項

- R009 scope は RuntimeHost 側の SSL-Vision receiver、latest packet buffer、configured interval operation loop、Core `TrackerCoordinator` normal path、official packet publish、latest snapshot store update に収まっている。R010 の manual evidence / final validation へ踏み込みすぎた差分は確認していない。該当箇所: `Tracker/Design/RuntimeHost/runtime-host-plan.md:106` から `:114`、`Tracker/Tracker.RuntimeHost/RuntimeHostServiceCollectionExtensions.cs:42` から `:68`。
- RuntimeHost project は `Tracker.Core` と hosting / options packages のみを参照している。DebugHost / Blazor / diagnostics replay UI / capture viewer project への参照は確認していない。該当箇所: `Tracker/Tracker.RuntimeHost/Tracker.RuntimeHost.csproj:10` から `:13`。
- `RuntimeHost:OperationLoopIntervalMilliseconds` は `RuntimeHostPeriodicTickSource` の `Interval` と `PeriodicTimer` 生成に使われており、operation loop 周期は code magic number ではない。R008 の 0 以下 validation も維持されている。該当箇所: `Tracker/Tracker.RuntimeHost/RuntimeHostPeriodicTickSource.cs:16` から `:31`、`Tracker/Tracker.RuntimeHost/RuntimeHostServiceCollectionExtensions.cs:23` から `:29`、`Tracker/Tracker.RuntimeHost/appsettings.json:21` から `:23`。
- receiver の multicast join / interface handling は、任意の `VisionReceiver:InterfaceAddress` 指定、候補 IPv4 interface discovery、全候補 join 失敗時の明示 error を持つ。現時点で RuntimeHost normal path blocker は見つけていない。該当箇所: `Tracker/Tracker.RuntimeHost/RuntimeVisionReceiverService.cs:105` から `:123`、`:132` から `:174`、`:177` から `:200`。
- public / internal API と `[Fact]` の XML summary は主要 surface で確認した。今回の blocking は documentation ではなく RuntimeHost tracker configuration resolver の behavior mismatch。
