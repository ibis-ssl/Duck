# 課題 #14: 比較構成の起動前準備

基点 `849664d5e92b3e5ff805514eca7d221fea9e2c67`。課題 #158 の Proto 検査とは独立。Windows 標準 launcher は補助プログラムを必要としない Compose を使い、比較 AppHost の直接起動では旧 DCP の CM4 補助が必要。以前の FA780 では同じネイティブ入力の CI 成果物で起動できたが、今回の欠落は CM4 の開始時まで検出されなかった。

## 設計と検査

- CI と明示ローカル準備で同じ Linux x64 静的生成スクリプトを使用する。生成時のソース9本と成果物のハッシュを一組にして、正規 CI バンドルへ追加する。ハッシュは完全性の検査であり、署名や供給元の認証ではない。正規の取得経路と CI のマニフェスト照合も必要。
- AppHost が構築時のソース9本と実行時の補助ファイルを照合し、必要な旧 DCP 構成に限り全資源の起動前のイベントで停止する。既存の CM4 個別開始時のファイル存在検査も維持。試合条件、初期配置、CM4 イメージ、既定 Compose は変更しない。
- Linux に既存コンパイラーがない場合、または Windows で正規成果物が入手できない場合は準備できない。自動取得やパッケージ導入で回避しない。
