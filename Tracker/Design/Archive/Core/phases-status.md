## 比較ログの成立条件

CaptureOn 中に受信できたトラッカーのパケットを session folder 配下の snapshot sidecar の JSONL に保存する。capture metadata から、各ファイルの相対パス、source identity、source role、比較元のパケットのバイト列または復元可能な参照をたどれる。公式のマルチキャスト受信は、明示的に有効化された場合だけマルチキャストグループへ参加する。

外部の tracker snapshot は、`Tracker.CaptureReplay` の CLI 出力、`/diagnostics` の比較表示、再生、Field source の切り替え、重ね合わせ表示で再生・比較できる。`ER-Force` のように `ibis` と tracked frame timestamp の時刻系が異なる場合も、新しいキャプチャーの保存時の対応付けを使って描画する。既存ログの救済は対象外であり、`SchemaVersion = 1` との互換性より、`SchemaVersion = 2` の索引による性能を優先する。

トラッカーの更新頻度が raw vision より高い場合、replay timeline は速い入力元の観測を含む。raw vision は対象時刻以前の最新の観測フレームを保持するため、低い頻度で更新される見え方が期待動作となる。ログを開くときに索引を作り、再生位置の更新時は高速に取得する。保存済みの対応付け、timeline scrubber、Field source、比較表示によって、任意の時点を比較できることを維持する。

等倍速の `Play` だけは、30fps相当で表示を更新する。再生開始からの wall-clock の経過時間を、開始時に選択した記録の受信時刻 `ReceivedAt` に加えて表示位置を決める。高頻度の観測は保存・比較用に保持したまま、表示では途中の時点を必要に応じて省略する。200Hzの入力と30fpsの表示でも実時間での遅れを確認できることを検証した。早送りは観測時点を間引かない。

`Play` / `Fast Forward` / `Stop` の従来のボタン配置を維持し、速度選択は `等倍速` と可変の `早送り倍率` を表示する。倍率を選んだ状態で再生しても等倍速へ戻さず、選択した倍率の早送りとして開始する。倍率は `2x..1024x` の範囲とし、64倍を超えてもタイマー間隔や状態の正規化で無効にならず、実効速度を上げられることを条件とする。
