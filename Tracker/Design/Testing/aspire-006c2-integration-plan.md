# ASPIRE-006C2 接続・性能検証計画

## 実装範囲

- PR #69 の情報源特定処理で解決した `Duck` / `TIGERs` / `ER-Force` の各役割の追跡記録を取得し、PR #70 の `TrackerDifferenceCalculator` へ渡す製品経路を追加する。
- 比較結果に情報源の識別情報、対象画像、機体と球の差分、欠落・未対応項目を結び付け、計算結果がどの二つの追跡記録に由来するか追跡できるようにする。
- Split / Overlay の画面描画更新から差分モデルを呼び出す配線や、描画と差分計算で同じ二つの追跡記録を共有する処理は含めない（Issue #41）。

## 重点連携試験

- 三つの役割がそれぞれ別の情報源として解決される入力を使い、解決済み追跡記録から差分計算まで製品経路を通す。
- 一致した機体・球の数と、欠落または対応付けできない対象の状態・一覧上の位置番号が計算結果まで保たれることを確認する。
- 役割の不足、役割の重複、識別情報の衝突、対象画像が無効な場合など、経路が成立しない状況での挙動を確認する。
- 既存の情報源特定処理や差分計算モデルを再実装せず、それらの公開された呼出方法を通して検証する。

## 性能測定

- 接続経路を含めて繰り返し実行できる専用の測定手順を追加する。新しい依存パッケージは導入しない。
- 代表的な通信パケットと画像データから機体数・球数を取得し、測定に使った入力件数を記録する。差分評価の呼出頻度は、実測した情報源の更新間隔と計測時間から算出して併記する。
- ならし処理の後、同じ二つの追跡記録を繰り返し評価し、処理時間の中央値・95パーセンタイルと、`GC.GetAllocatedBytesForCurrentThread` で測った呼出当たりの割当量を記録する。
- .NETの版、基本ソフト、CPU、入力件数、追跡記録の選択・情報源特定・差分計算のどこまでを測ったか、ならし処理と反復回数を記録する。未計測の性能目標や比較対象を達成した扱いにしない。

## 検証の順序

- 接続箇所の機能単位の試験を先に追加し、実装前に失敗することを確認する。
- 接続経路、失敗時の挙動、測定手順を実装し、機能単位の試験とコンパイルを実行する。
- 全構成の検証には既存のAspire/Linux受入経路を再利用する。新しい環境設定が必要になった場合はそこで停止し、親へ報告する。
- 結果は実際に検証したコミット識別子とともに記録する。
