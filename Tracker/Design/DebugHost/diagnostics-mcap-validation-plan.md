# 診断ログの追加検証計画

## 目的

[課題 #151](https://github.com/ibis-ssl/Duck/issues/151) のうち、[先行実装の変更 #154](https://github.com/ibis-ssl/Duck/pull/154) で確定していない検証を整理する。起動ごとに診断ログを一つの MCAP ファイルにまとめる構成は変更しない。

## 方針

先行実装では、Linux 上で Aspire を使わずに動く本番ホストと開発用ホストを正常終了し、それぞれの MCAP を読み戻した。開発機でも診断ログの読み戻しは確認したが、試合は完走していない。負荷と強制終了時の回収は旧版の限定的な測定であり、現行版の測定結果として扱わない。

まず既存の検証手順と固定版を使う。Windows での記録と正常停止、負荷の測定、異常終了の確認を別々に行い、どの条件で何が起きたか追えるようにする。今回の下書きは計画のみで、コード・イメージ・依存・運用設定を変更せず、試験は未実施。

## 検証の詳細

| 検証 | 手順の要点 | 残す証拠 |
|---|---|---|
| Windows での正常停止 | Windows 検証環境の既存の固定構成を使う。本体と開発用ホストは個別に起動し、通常の停止操作で終了させる | 対象コミット、実行条件、終了値、各起動で完成したファイルの本数、時刻・発生元・重要度・終了時の記録、旧形式の新規出力の有無 |
| 記録負荷 | 現行実装の同一版・同一環境で、同じ入力を記録なしと記録ありで比較する。件数と負荷条件を固定し、低負荷と連続出力の条件は混ぜない | 件数、計測時間、処理時間の分布、欠落、終了までの時間、ファイル容量。評価の基準を決めていない数値は合否と混同しない |
| 異常停止からの回収 | ユーザーの保存先と分離した試験フォルダーを使い、既知の連番を記録する。正常停止の対照と、試験プロセスのみを強制終了する条件を分ける | 予定件数、最後に読み戻せた番号、欠落、未確定ファイルの扱い、再起動後の新しいファイルと保存済みファイルの保全。マシンの電源は切らない |
| 診断画面での確認 | 記録した MCAP を開き、表示件数、読み飛ばし、表示上限による省略の表示を確認する | 元ファイルとの件数照合と画面上の結果。表示上の省略は記録の欠落として扱わない |

## 完了条件

- 各検証の対象版、手順、結果と未確認点を記録する。合成データと本体の実動作、正常停止と強制終了を区別する。
- 想定と違う場合は最初に既存手順と固定構成との差を調べ、対策の必要性と影響を示す。調査中に機能や依存を足さない。
- 入力から読み戻しまで確認できる証拠をまとめ、独立レビューに渡す。未実施を成功として記載しない。

## 保留

Windows の通常ユーザー（非管理者）で起動できるかを確認する専用試験は、必要になるまで実施しない。非管理者での動作が明示要件になったとき、または権限の違いが事象に関係すると分かったときに再開する。Windows での MCAP 記録・正常停止の確認とは別に扱う。

## 対象外

AutoRef のクラウド構築準備は [変更 #162](https://github.com/ibis-ssl/Duck/pull/162) と分ける。録画開始用ファイルのイメージ同梱、生の試合イベントの収録、試合の完走自体、外部製品ログの統合、計算機の電源断試験はこの下書きの対象に含めない。
